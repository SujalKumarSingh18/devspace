# 1. 🔀 The Request-Response Cycle (Visualized)

Here is a visual map of the data flow when a developer registers on DevSpace:

```text
[ Browser Client ]
       │
       ▼ (1. POST request with username, email, password)
[ Next.js API Route Handler ]
       │
       ├─► 2. Runs dbConnect() ──► Check Cache ──► Connects to MongoDB Atlas
       ├─► 3. Parses request body: await req.json()
       ├─► 4. Checks DB: User.findOne({ email/username })
       │         │
       │         └─► User exists? ──► Return 400 "User already exists"
       │
       ├─► 5. Hashes password: bcrypt.hash(password, 12)
       ├─► 6. Saves User: User.create({ username, email, passwordHash })
       │
       ▼ (7. Success!)
[ Return NextResponse.json({ message: "Registered!" }, { status: 201 }) ]
```

# 2. 🗄️ Mongoose Architecture: Interfaces, Schemas & Models

In a TypeScript MERN app, Mongoose operates in three layers:

```text
┌──────────────────────────────────────────────┐
│   1. TypeScript Interface (IUser)            │ ──► Type checks inside your code editor
└──────────────────────┬───────────────────────┘
                       │ (defines types for)
                       ▼
┌──────────────────────────────────────────────┐
│   2. Mongoose Schema (UserSchema)            │ ──► Validates structure at runtime (MongoDB types)
└──────────────────────┬───────────────────────┘
                       │ (compiles into)
                       ▼
┌──────────────────────────────────────────────┐
│   3. Mongoose Model (User)                   │ ──► The controller you call to perform queries
└──────────────────────┬───────────────────────┘
                       │ (reads/writes to)
                       ▼
┌──────────────────────────────────────────────┐
│   4. MongoDB Collection (users)              │ ──► Real database documents stored in cloud
└──────────────────────────────────────────────┘
```

### 🔍 Mongoose Queries Cheat Sheet

* **Create a document:**
  ```typescript
  await User.create({ username, email, passwordHash });
  ```
* **Find first match:**
  ```typescript
  const user = await User.findOne({ email }); // Returns user object or null
  ```
* **Find by ID:**
  ```typescript
  const user = await User.findById(userId);
  ```
* **Count documents:**
  ```typescript
  const count = await User.countDocuments();
  ```
* **Save updates on a document instance:**
  ```typescript
  const user = await User.findById(id);
  user.reputation += 10;
  await user.save();
  ```

# 3. 🔐 bcryptjs: Cryptographic Security & Hashing

Passwords must never be stored as readable text. We use `bcryptjs` for one-way cryptographic hashing:

```text
🔒 REGISTRATION FLOW (Hashing)
[Plain Password: 'mySecret123'] ──► bcrypt.hash (12 salt rounds) ──► Stored Hash: '$2a$12$7kP.yG8QW6...'

🔑 LOGIN FLOW (Comparing)
[Login Input: 'mySecret123'] ──┐
                               ├──► bcrypt.compare ──► Matches? ──► YES (Allow Access)
[Stored Hash: '$2a$12$...'] ───┘                                └──► NO  (Deny Access)
```

* **`bcrypt.hash(password, saltRounds)`**: Generates an encrypted hash. Increasing salt rounds increases computational security (12 is standard).
* **`bcrypt.compare(passwordInput, storedHash)`**: Safely compares input with hash and returns `true` or `false`.

# 4. 🔀 Next.js API Routes vs Traditional Express

| Feature | Express.js | Next.js App Router |
| :--- | :--- | :--- |
| **Route Declaration** | `app.post('/api/auth/register', (req, res) => {})` | File `src/app/api/auth/register/route.ts` exporting `export async function POST(req: Request)` |
| **Parsing Request JSON** | `const { email } = req.body;` | `const { email } = await req.json();` |
| **Sending JSON Responses** | `res.status(201).json({ message: "Success" });` | `return NextResponse.json({ message: "Success" }, { status: 201 });` |
| **Request Cycle End** | Automatically ends when `res.json()` is called. | Ends when the handler function returns a `Response` object. |
